# AKS module feature test plan

## Context

The basic cluster (`test-aks`, `EMEA-Cloud-Sandbox-DEV-RG`, sub `1ee6dc45-…`, uksouth, custom VNet + overlay + UDR, node RG `MRG_AKS-test-aks-DEV-RG`) now deploys. Baby wants to exercise every other module input and confirm each in the Azure portal. Deliverable: a table — **Feature | Code | Results | What it is / used for** — grouped into phases ordered so in-place changes come first, lockout/recreate risks last, and features blocked by CBRE policy or Contributor-only access are flagged rather than attempted blind.

On approval: save this plan (Phases 0–6, blocked list, verification) as `TESTING.md` in the `terraform-azurerm-aks` directory (repo root, next to `main.tf`). Keep it local, not for commit: the Update a Terraform Module procedure puts test material in `cloud-deploy-tfe-module-factory`, and the Terraform Structure Standards don't allow extra files in a module repo. Then walk the phases with Baby one at a time.

**Conventions in the Code column**
- *Module* = where the feature is implemented (`main.tf` / `variables.tf` / `diagnostics_*.tf` line numbers as of today).
- *test.tf* = what to add. Unless stated, add **inside `module "aks"`, after `network_profile` (currently [deploy/test.tf:95-99](deploy/test.tf))**. Line numbers in test.tf shift as phases are added; anchor on the block, not the number.
- Run `terraform plan` before every apply and check for **"must be replaced"** on `module.aks.azurerm_kubernetes_cluster.aks` — only Phase 6 items should replace the cluster.

## Verification (per phase)

1. `terraform plan` — expect in-place updates only (Phases 1-5); stop if the cluster shows "must be replaced".
2. `terraform apply`, then the portal checks in the Results column.
3. Record pass/fail and any policy deny message in `TESTING.md`.
4. After all phases: revert cost items (`sku_tier`, Defender, Spot), then `terraform destroy` (procedure step 14) and remove leftovers (`MC_EMEA-Cloud-Sandbox-DEV-RG_test-aks_uksouth`, failed clusters/identities in `US-CloudEng-Model-RG`).
